# float-format

按十进制规则格式化数值（四舍六入五成双、千分位、负零归一），只用 Go 标准库。

```
go test ./...
go run ./cmd/float-format --format 2.675 --digits 2
go run ./cmd/float-format --format 1234567.891 --digits 2 --group
```

## 口径（README 为准）

- **按十进制字符串做舍入**（不许先转 float 再 `Sprintf`）：`2.675` 保留 2 位必须是 `2.68`，
  现在因为二进制表示是 `2.67499…` 给出 `2.67`。
- **四舍六入五成双**：`--format 2.5 --digits 0` 给 `2`、`--format 3.5 --digits 0` 给 `4`。
- **千分位**：`--group` 时整数部分每三位加逗号：`1234567.891` 保留 2 位应是 `1,234,567.89`，
  现在原样给 `1234567.89`。
- **负零归一**：`--format -0.001 --digits 2` 按口径是 `0.00`（现在是 `-0.00`）。
- 不变量：输出的小数位数恰好等于 `--digits`；同一输入重复格式化结果相同；
  与「按十进制字符串手工舍入」的参考实现逐字符一致。
- 规模：100 万次格式化线性完成，输入字符串长度 ≤ 1 万位也不许退化成 O(n²)。

## 现在的行为

- `Format` 直接 `strconv.ParseFloat` + `fmt.Sprintf("%.*f", digits, number)`：一切按二进制浮点来，
  `2.675` 给出 `2.67`。
- `--group` 被 `_ = group` 忽略，千分位从来不生效。
- 舍入交给 `%f`（就近偶数，但作用在二进制值上），十进制上下文里会给出意外结果。
- `-0.00` 不会被归一成 `0.00`。

## 计划新增的能力

```
--digits N     保留几位小数（默认 2）
--group        整数部分加千分位
```

## 输出

```
格式化后的数值
```
